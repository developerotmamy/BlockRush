# BlockRush — архитектура модов

Документ для людей и для ИИ-ассистентов, которые пишут или правят моды для BlockRush.
Источник правды — секция «МОДЫ» в `block_Rush_mods.html` (в файле примерно строки 4440–4690; номера могут уплыть, ищи по именам функций).

---

## 0. TL;DR

- **Мод — это один JSON-файл** (≤ 512 КБ) с метаданными, необязательным блоком `data` (декларативные машины) и необязательным `script` (JS-код).
- Моды хранятся в `localStorage` браузера, грузятся **один раз при старте страницы**. Любое изменение (вкл/выкл/установка/удаление) требует **перезагрузки игры**.
- Декларативная часть (`data.cars`) относительно безопасна: это только числа и описание кузова.
- `script` выполняется через `new Function` **без песочницы** — это полный доступ к странице. Поэтому при установке есть `confirm`.
- Игра не падает от плохого мода: ошибки ловятся, мод помечается как failed, а при двух подряд неудачных запусках включается **безопасный режим** (все моды отключены).

## 1. Жизненный цикл

```
Установка (вставка / drag&drop / каталог)
   │  parseMod() → валидация JSON
   │  если есть script → confirm()
   ▼
MODS[id] = { text, on, ver, name, author, script }  ──►  localStorage "blockrush.mods"
   │
   ▼   (перезагрузка страницы)
loadMods()
   ├─ счётчик запусков "boot" ≥ 2 ?  → безопасный режим, моды НЕ грузятся
   ├─ boot++ ; через 6 сек boot = 0 (игра «дожила»)
   ├─ для каждого включённого мода (по алфавиту id):
   │     run(id):
   │       1. parseMod(text) заново
   │       2. requires[] → зависимости запускаются первыми (рекурсивно)
   │       3. makeAPI(id)
   │       4. data.cars[0..19] → api.cars.add()
   │       5. script → new Function('BR','mod','"use strict";' + script)(api, m)
   │       6. успех → modInfo.loaded, ошибка → modInfo.failed
   └─ BR.sig = "id@version,id@version,…"   (подпись набора модов)
```

Что важно:

- Порядок запуска: **алфавитный по id**, кроме зависимостей (`requires`) — они идут раньше зависимого мода. Повторный запуск одного и того же мода защищён множеством `done`, так что циклические зависимости не зависают.
- Если зависимость отсутствует или выключена → зависимый мод попадает в `failed` с текстом «нужен мод …».
- Данные (`data`) применяются **до** скрипта, поэтому скрипт может использовать уже добавленные машины (`api.cars.list()`).
- После загрузки сохранённая машина игрока восстанавливается, если её id — модовый (`localStorage "blockrush.car"` ≥ 4).

## 2. Формат мода

```jsonc
{
  "id": "my-mod",            // ОБЯЗАТЕЛЬНО. ^[a-z0-9][a-z0-9-]{1,39}$  (2–40 символов, a-z, 0-9, дефис)
  "name": "Мой мод",         // ОБЯЗАТЕЛЬНО (в UI обрезается до 40 символов)
  "version": "1.0",          // строка, в UI до 12 символов; по умолчанию "1"
  "author": "ник",           // до 30 символов
  "api": 1,                  // версия API; если > 1 — мод отклоняется («нужна более новая игра»)
  "requires": ["other-mod"], // id модов, которые должны быть установлены И включены
  "data": { "cars": [ /* описания машин, максимум 20 */ ] },
  "script": "BR.toast('привет');"   // JS-код одной строкой (экранируй кавычки и переносы по правилам JSON)
}
```

Ограничения парсера (`parseMod`):

| Проверка | Результат при нарушении |
|---|---|
| Текст не строка или > 524 288 символов | «Мод слишком большой (максимум 512 КБ)» |
| Не JSON | «…это не JSON» |
| id не соответствует regex | «Неверный id мода» |
| `api` > 1 | «Мод требует более новую версию игры» |
| Нет `name` | «У мода нет названия» |

Весь пользовательский текст (имена, описания) пропускается через `clean()` — из него вырезаются `< > & " ' \`` и обрезается длина. Не рассчитывай на HTML или кавычки в названиях.

## 3. Машины (`data.cars[]` и `api.cars.add`)

Новая машина создаётся **на основе существующей** (`base`) — копируются все её параметры, затем поверх накладываются твои.

```jsonc
{
  "name": "Мини",              // до 24 символов
  "desc": "Маленькая и юркая.",// до 160 символов
  "cls":  "хэтчбек",           // ярлык класса, до 24 символов, приводится к ВЕРХНЕМУ РЕГИСТРУ (по умолчанию "МОД")
  "base": 0,                   // индекс базовой машины: 0 седан, 1 купе, 2 формула, 3 грузовик (неверный → 0)
  "color": "#3fa7e8",          // "#rrggbb" или число 0xRRGGBB; по умолчанию цвет базы
  "boost": false,              // есть ли буст (Shift / кнопка BOOST)
  "ui": { "acc": .5, "spd": .5, "hnd": .6, "drift": .4, "wgt": .3 }, // полоски в гараже, 0..1
  "tune": { "mass": 0.9, "A0": 10, "vmax": 60 },   // переопределение физики (см. ниже)
  "shell": { /* кастомный кузов, см. ниже; без него берётся модель базы */ },
  "extras": [ ["B", 0, 1.4, -1.8, 1.6, .08, .4, false] ],  // доп. кубики
  "traffic": { "w": 3, "cruise": [10, 16], "wob": 0 }      // появление в трафике (необязательно)
}
```

### 3.1 Что делает `addCar` (по шагам)

1. Берёт `S = { ...CARS[base], ...tune }`.
2. Если есть `shell` — проверяет, что **все 13 ключей** кузова (`hw, zf, zr, wx, ww, wzF, wzR, wr, roof, zb0, zb1, zt0, zt1`) — конечные числа, иначе ошибка `shell.<ключ> должен быть числом`. Затем выставляет из шасси: `a = wzF`, `b = -wzR`, `tx = wx`, `wr = wr` — и **после этого** снова накладывает `tune` (то есть `tune` имеет приоритет).
3. Присваивает новый `id` (= текущая длина `CARS`, то есть **следующий по порядку**), помечает `S.mod = id мода`.
4. Любое нечисловое/`NaN` поле физики заменяется значением из базы.
5. `finishCar(S)` пересчитывает производные величины: пятна контакта `pkF/pkR`, длину `len`, точки колёс `fxw`, контрольные точки столкновений `pts`, моменты инерции.
6. Собирает функцию построения модели и делает **пробную сборку** на временном материале. Если модель ломается — исключение, машина не добавляется, мод идёт в `failed` (сломанная модель не попадёт в игру).
7. Регистрирует машину во всех реестрах: `BUILD`, `PROXY_DEF` (упрощённая модель для дальнего LOD берётся **от базы**), `CARS`, и (если задан `traffic`) `NPC_TYPES`.

Вернёт числовой `id` новой машины.

### 3.2 Физика (`tune`)

Любое поле из встроенных `CARS[0..3]` можно переопределить. Названия — как в коде игры:

| Группа | Поля |
|---|---|
| Масса и геометрия | `mass`, `a`, `b` (расстояния до осей), `iz`, `r`, `off[]`, `wr` (радиус колеса), `tx` (полуколея), `ez` |
| Мотор/трансмиссия | `A0` (разгон), `vmax`, `launch`, `gears`, `shift`, `brake`, `drvF` |
| Шины/сцепление | `muF`, `muR`, `Bf`, `Cf`, `Br`, `Cr`, `flF`, `flR`, `dfk` (прижимная сила) |
| Руление | `steerLock`, `steerSpd`, `steerMin`, `steerRate`, `assist`, `assistW` |
| Ручник/занос | `hbKeep`, `hbMu`, `yawDamp` |
| Задний ход | `revMax`, `revAcc` |
| Крен/клевок, следы | `roll`, `pitch`, `skidW` |
| Камера и гараж | `camDist`, `camY`, `showR`, `showH` |
| 3D-физика | `cy` (высота центра масс), `top` (высота крыши), `tipAy` (порог опрокидывания) |

> **Совет.** Если у твоей машины кузов заметно другой длины/высоты, чем у базы, переопредели ещё `off` (массив смещений контрольных точек по длине), `r` и `top`. От них считается хитбокс (`len`, `pts`). Иначе машина будет «чувствовать» себя размером с базу.

### 3.3 Кузов (`shell`)

Параметрический «лего-кузов». Координаты: `x` — вбок, `y` — вверх, `z` — вперёд (перед машины = `+z`). Единицы — внутриигровые.

| Ключ | Значение |
|---|---|
| `hw` | полуширина кузова |
| `zf`, `zr` | вынос вперёд / назад от центра (длина = `zf + zr`) |
| `wx` | поперечное положение колёс |
| `ww` | ширина колеса |
| `wzF`, `wzR` | продольное положение передней / задней оси (`wzR` обычно **отрицательное**) |
| `wr` | радиус колеса |
| `roof` | высота крыши |
| `zb1`, `zb0` | нижние точки передней и задней стойки (основание лобового / заднего стекла) |
| `zt1`, `zt0` | верхние точки тех же стоек (вершина крыши) |
| `drv` *(опц.)* | поперечное положение водителя (по умолчанию `.4`) |
| `sz` *(опц.)* | продольное положение передних сидений |
| `rz` *(опц.)* | положение заднего сиденья |
| `bOff` *(опц.)* | сдвиг средней стойки |

Рабочий ориентир — параметры седана: `hw 1.0, zf 2.1, zr 2.1, wx .95, ww .32, wzF 1.35, wzR -1.35, wr .42, roof 1.52, zb1 .82, zt1 .5, zb0 -.95, zt0 -.78`.

Здравые соотношения (иначе панели «вывернутся»): `zf > wzF + wr + .1`, `zr > -wzR + wr + .1`, `zt1 < zb1`, `zt0 > zb0`, `roof` выше линии капота.

### 3.4 Доп. детали (`extras`)

До 300 элементов. Каждый — массив `[материал, x, y, z, w, h, d, шипы?]`:

- `x, y, z` — центр кубика, `w, h, d` — размеры по x/y/z. Шесть чисел обязательны (иначе элемент молча пропускается).
- `материал`: `"B"` — материал кузова (перекрашивается вместе с машиной) или ключ из `MAT`: `glass, dark, head, tail, wheel, hub, white, cargo, teal, win, trim, seat, dash, carpet, crate, wood`. Неизвестный ключ → `trim`.
- Последний параметр — рисовать ли «шипы» лего (по умолчанию `false`).

### 3.5 Трафик (`traffic`)

Добавляет тип в `NPC_TYPES`: `w` — вес появления (0–20; у встроенных: 6/5/2/3), `cruise: [мин, макс]` — крейсерская скорость, `wob` — «рыскание» по полосе (0 = едет ровно).

## 4. Script-API (`BR`)

Скрипт получает два аргумента: `BR` (API) и `mod` (разобранный JSON самого мода). Выполняется в `"use strict"`.

### 4.1 Общий объект

| Имя | Что это |
|---|---|
| `BR.version` | `1` |
| `BR.sig` | подпись загруженных модов, `"id@ver,…"` |
| `BR.THREE` | библиотека three.js |
| `BR.scene`, `BR.camera` | сцена и камера |
| `BR.state` | `{ mode }` — `'menu'`, `'play'`, `'garage'` |
| `BR.player` | машина игрока (объект vehicle) |
| `BR.me` | аватар-человечек |
| `BR.vehicles`, `BR.npcs` | массивы всех машин / NPC |
| `BR.MAT` | реестр материалов |
| `BR.clamp(v, a, b)`, `BR.toast(text)` | утилиты |
| `BR.on(event, fn)` | подписка на событие |
| `BR.emit(event, a, b)` | вызвать событие (игра использует сама) |
| `BR.traffic.add({id, w, cruise, wob})` | добавить тип в трафик |
| `BR.spawn(carId, x, z, h=0, color?)` | создать машину в мире, вернёт vehicle |
| `BR.ui.addMenuButton(label, fn)` | кнопка в главном меню (до 30 символов) |
| `BR.ui.addChip(text)` | плашка в верхней панели HUD (до 40 символов) |

### 4.2 Персональный API мода (то, что реально приходит в `BR`)

`makeAPI(id)` создаёт `Object.create(BR)` и добавляет:

| Имя | Что делает |
|---|---|
| `BR.id` | id текущего мода |
| `BR.cars.add(def)` | то же, что `data.cars[i]`; вернёт id машины |
| `BR.cars.patch(carId, obj)` | `Object.assign` в спецификацию **любой** машины (в т.ч. встроенной) + пересчёт `finishCar` |
| `BR.cars.list()` | `[{id, name}]` всех машин |
| `BR.storage.get(key, default)` / `.set(key, value)` | персональное хранилище мода в `localStorage`, ключ `blockrush.m.<id>.<key>` (ключ до 30 символов, значение — JSON-сериализуемое) |

### 4.3 События

| Событие | Когда | Аргументы |
|---|---|---|
| `start` | игрок нажал «играть», режим стал `'play'` | — |
| `checkpoint` | взят чекпоинт | `score` (новый счёт) |
| `tick` | каждый кадр | `dt` (секунды) |

Особенности `emit`: каждый обработчик вызывается в `try/catch`. **Если обработчик бросил исключение — он навсегда отключается** до перезагрузки, а игрок видит тост «Ошибка в моде — обработчик отключён». Подписывайся на события во время загрузки мода; `tick` вызывается каждый кадр, не делай там тяжёлую работу и не создавай объекты без нужды.

## 5. Установка и интерфейс

Окно «Моды» (кнопка в меню) имеет три вкладки:

1. **Установлено** — список модов: переключатель Вкл/Выкл, удаление `×`, пометка «· код» у модов со скриптом, красная строка ошибки, если мод в `failed`.
2. **Каталог** — удалённый список модов (см. §6).
3. **Вставить** — вставка текста JSON.

Также можно **перетащить файл мода на страницу** (drag&drop). После любого изменения появляется кнопка «Перезагрузить игру, чтобы применить». Если игрок в онлайн-комнате, перезагрузка требует подтверждения, потому что он выйдет из комнаты.

## 6. Каталог модов

Каталог — это статический сайт (обычно GitHub Pages) с файлом `index.json`.

**Ввод адреса:** либо `ник/репозиторий` (превращается в `https://ник.github.io/репозиторий/`), либо полный `https://…`. Только HTTPS.

**`index.json`** — массив (максимум 100 записей):

```json
[
  {
    "id": "demo-mini",
    "name": "Демо: Мини",
    "author": "you",
    "version": "1.0",
    "desc": "Маленький хэтчбек",
    "url": "mods/demo-mini.json",
    "sha256": "<хеш файла, необязательно>",
    "type": "script"
  }
]
```

Правила скачивания (`downloadMod`):

- `url` разрешается относительно адреса каталога; файл **обязан лежать внутри каталога**, иначе ошибка.
- Если указан `sha256` — хеш скачанного текста сверяется (если браузер умеет `crypto.subtle`); при расхождении установка отменяется.
- `id` внутри скачанного мода обязан совпадать с `id` в каталоге.
- `type: "script"` — **только метка в списке** («· код»). Настоящая проверка — наличие `script` в самом моде (именно по ней показывается предупреждение).
- Если версия в каталоге отличается от установленной — кнопка превращается в «Обновить».

## 7. Мультиплеер

- Хост в приветственном сообщении (`t: 'w'`) отправляет свою подпись `BR.sig`.
- Если у гостя подпись отличается, ему показывается тост «Моды отличаются от хоста: …». Это **предупреждение, а не блокировка** — игра не мешает зайти.
- Id машин модов выдаются **последовательно в порядке загрузки**. Если у игроков разные наборы/версии модов, один и тот же `carId` может означать разные машины (или не существовать). Для комфортной игры нужны **одинаковые наборы модов и версии**.

## 8. Безопасность и защита от поломок

| Механизм | Что делает |
|---|---|
| `confirm` при установке | Для модов со `script` показывает предупреждение: код может делать что угодно, включая чтение данных игры в браузере. |
| Флаг `MODS[id].script` | Скрипт запускается только если он и есть в моде, и был подтверждён при установке. |
| Валидация и `clean()` | Ограничивают длины, чистят строки, подменяют `NaN` числами базы. |
| Пробная сборка модели | Сломанная геометрия машины не попадёт в игру. |
| `try/catch` вокруг загрузки | Ошибка в одном моде не мешает остальным; причина видна в окне «Моды». |
| Отключение сбойных обработчиков | Один исключительный `tick` не будет ронять игру каждый кадр. |
| Безопасный режим | Если игра запускалась с ошибкой дважды подряд (счётчик `boot` ≥ 2) — моды не загружаются, показывается тост. В окне «Моды» видно, что режим включён; отключи подозрительный мод и перезагрузи. |
| `sha256` в каталоге | Защищает от подмены файла относительно записи каталога. |

> **Честно о рисках.** `new Function` не песочница: скрипт мода видит `window`, `localStorage`, сеть. Модами со `script` нужно доверять так же, как расширению браузера. Моды, содержащие только `data`, значительно безопаснее.

## 9. Чек-лист для автора (и для ИИ, который пишет мод)

1. `id`: только `a-z`, `0-9`, `-`, 2–40 символов, уникальный. `name` обязателен.
2. `api: 1`. Не ставь больше.
3. Используй `data.cars`, если хватает декларативного описания. `script` — только когда нужна логика.
4. Для кузова заполни **все 13** ключей `shell` числами; проверь соотношения из §3.3.
5. Если кузов отличается размерами от базы — задай `off`, `r`, `top` в `tune`.
6. В `extras` все 6 числовых полей обязательны; материал `"B"` — перекрашиваемый.
7. Скрипт — одной JSON-строкой: кавычки внутри используй одинарные или экранируй, переносы пиши `\n` или объединяй через `;`.
8. Не полагайся на порядок загрузки между независимыми модами; нужен другой мод — пиши `requires`.
9. В `tick` — минимум работы; в обработчиках — защитные проверки (иначе обработчик отключится после первой ошибки).
10. Данные мода храни через `BR.storage`, а не придумывай свои ключи в `localStorage`.
11. После каждого изменения версии поднимай `version` — по нему каталог предлагает «Обновить», а мультиплеер сверяет подписи.
12. Проверка: установи, перезагрузись, посмотри окно «Моды» — красная строка покажет причину отказа.

## 11. Ограничения API v1 (чего пока нет)

- Нельзя без скрипта менять карту, трассу, здания, звук или HUD — только машины и трафик.
- Нет горячей перезагрузки: любое изменение = перезапуск страницы.
- Встроенных событий четыре: `start`, `checkpoint`, `tick` и `ready` (только в сборке с полным доступом, см. §12). Всё остальное — через `BR.patch`.
- Нет отписки от события (`BR.off`).
- Нет автоматической синхронизации модовых данных между игроками, кроме предупреждения о различии подписи.
- `PROXY_DEF` (дальний LOD) копируется от базы, поэтому издалека машина выглядит как упрощённая база.

## 12. Полный доступ к игре (сборка `block_Rush_mods_full.html`)

Обычный `BR` отдаёт только небольшую часть игры: основной скрипт — ES-модуль, и его внутренние переменные и функции снаружи не видны. В сборке с патчем `patch_full_access.mjs` моды получают доступ ко **всему, что объявлено на верхнем уровне модуля**.

### Что делает патч

1. Все `const` верхнего уровня заменены на `let` (176 объявлений), чтобы любое значение можно было переприсвоить. `GRAV`, например, был `const`.
2. В `BR` добавлены:

| Имя | Что делает |
|---|---|
| `BR.full` | `true`, если сборка с полным доступом. Для проверки: `if (!BR.full) throw …` |
| `BR.G` | Прокси ко всем переменным модуля: `BR.G.CARS`, `BR.G.GRAV = 5`, `BR.G.groundH(x, z, y)` |
| `BR.scope(code)` | Выполнить JS-код **внутри** модуля (прямой `eval`), с доступом ко всем его именам |
| `BR.patch(name, make)` | Заменить функцию игры обёрткой: `BR.patch('groundH', orig => (x, z, y) => orig(x, z, y) + 2)` |

3. Добавлено событие `ready`: оно вызывается после полной инициализации игры, перед запуском главного цикла.

### Важное правило: используй `ready`

Моды загружаются **посреди** инициализации. Всё, что объявлено в файле ниже `loadMods()` (главный цикл, настройки, часть HUD), на этот момент ещё недоступно: чтение даёт `undefined`, запись бросает ошибку. Поэтому код, который трогает внутренности, нужно оборачивать в `BR.on('ready', () => { … })`.

### Пример

```js
if (!BR.full) throw new Error('Нужна версия игры с полным доступом');
BR.on('ready', () => {
  BR.G.GRAV = 3.5;                                     // гравитация
  BR.patch('groundH', orig => (x, z, y) => orig(x, z, y) + Math.sin(x * .05) * 2);
  BR.scope('NPC_TYPES.length = 0');                    // выполнить произвольный код в модуле
});
```

Готовая демонстрация — `moon-gravity.json` (плашка «Луна» переключает гравитацию).

### Что всё равно недоступно

- Переменные внутри анонимных функций и блоков (замыканий) верхнего уровня. Они приватные: это несколько безымянных `(() => {...})()` и блок `{ … }` в районе обработчиков ввода и сети. Доступ даёт только то, что игра сама вынесла наружу.
- Внутренности Rust/WASM-физики: из JS видны только её входы и выходы, но не расчёт.
- Значения, которые игра один раз скопировала в другие структуры при старте. Изменение исходной переменной их не обновит.
- Заменённая через `BR.patch` функция действует для вызовов по имени, но не для ссылок, которые игра успела сохранить раньше.

### Безопасность и производительность

`new Function` и раньше давал модам доступ ко всей странице, так что новых прав патч не выдаёт, но делает их удобнее и «ломать игру» теперь проще. Безопасный режим остаётся единственной защитой. Прямой `eval` и `let` вместо `const` могут чуть уменьшить оптимизации движком; на практике заметно только на очень слабых устройствах.

### Как применить патч к новой версии игры

```
npm i acorn
node patch_full_access.mjs block_Rush.html block_Rush_full.html
```
